# Architecture

A map of the plugin as of **0.27.0** (`plugin/foxfire-studio/`). Line numbers drift, so search for the comment headings instead.

The theme template used before 0.1.0 was the same page in one file (PHP, CSS, HTML and script together). It has been retired; it stays in the history and the v0.0.x releases.

## 4. JavaScript (the studio's files)

Until 0.25.2 the studio was one immediately-invoked function in `teleprompter.js`. It is now eight, one per file, loaded in this order after the engines (clean.js, readout.js, compare.js, whisper.js and the others): `studio-core.js`, `record.js`, `cues.js`, `voice.js`, `master.js`, `review.js`, `editor.js`, then the starter `teleprompter.js`. Since 1.3.0 `takes.js` (Combine takes) loads after `editor.js`, since 1.5.0 `prompter.js` (prompter view) after `takes.js`, since 1.12.0 `phonetake.js` (phone take mode) right after `record.js`, with its engine `live.js` among the engines, and since 1.13.0 `hearpolish.js` (voice polish) right after `review.js`, with its engine `polish.js` among the engines. Since 1.14.0 `follow.js` (voice following's pure parts) is the last engine; `voice.js` keeps its place and starts `follow-worker.js`, which is not a page script. The code was moved as it was and runs in the same order as before.

They share one object, `window.RRTStudio`, which studio-core.js makes and every file calls `studio`:

- A name another file needs (an element, a function, a setting) is put on it once: functions at the top of their file (`studio.fmt = fmt;`), other names just after they are set (`studio.settings = settings;`). A file that loads later borrows it at its top (`var settings = studio.settings;`), as the engines are borrowed. A file that loads earlier reads `studio.name` when it needs it, which is only ever after the page has loaded.
- A name that changes after it is first set (`playing`, `wi`, `pos`, `finished`, `takeMode`, `unsaved` and the rest) lives on it in every file, as `studio.playing`, so every file sees the same value.
- Each file stops where the one function used to when no post is chosen (`if (!track) { return; }`), so without a post only the settings, the post menu, the intro, recovery and Send to my computer run.
- Each file is its own script handle (`rrt-studio-core` and so on, each needing the one before it), so each has its own translations.

## 5. Data flow of a recorded take

```
mic ─► AudioWorklet capture (raw, held while the reading pauses) ─► 16-bit WAV
   │        ├─► IndexedDB, about once a second (crash recovery)
   │        └─► on a phone (1.12.0): pieces of 10 s ─► rrt/v1/sent/<id>/piece ─► uploads/rrt-sent/<id>.wav (at Stop: done, waits for the computer)
   └─► or MediaRecorder (WebM/M4A) where AudioWorklet cannot run
          │
          ▼  buildFile()
   decode at 44.1 kHz mono ─► trim ends ─► denoise.js worker (48 kHz, RNNoise) or deepfilter.js worker (1.16.0, falling back to RNNoise) ─► cleanReading() ─┬─► sound.js worker: pops ─► 80 Hz high-pass ─► breaths
                                                            │      ─► de-esser ─► compressor ─► BS.1770 loudness ─► true-peak limiter
                                                            │      ─► fades ─► mp3.js worker (LAME, mono or stereo) or a 48 kHz WAV (1.6.0) ─► decode ─► studio check
                                                            │      ─► (if loudness is off by more than 0.3 dB) adjust ─► MP3 again ─► check
                                                            └─► (sound off, or on failure) levelSimple() ─► fades ─► mp3.js worker (LAME)
          │                                     │
          │                                     └─► room report
          ▼
   analyseReading()  ─► "How it went" read-out
          │
          ▼  runReview()  (if Whisper review is on), given the untouched trimmed audio
   to16k() ─► Web Worker: Whisper (word timestamps)
          │
          ▼
   compareReading(script, heard words, pitch/loudness frames, learned words)
          │
          ▼
   showReview(): tiles, flags, timeline, marked script, takes, captions (.vtt)
          │
          ▼  Download, or Use this recording (master.js)
   the take, or the edited MP3 ─► with the music bed switched on: music mixed under the voice ─► leveled again ─► MP3
```

| Store | Holds |
|---|---|

The self-hosted Whisper copy is downloaded one file at a time by the settings screen. Each file is checked against the SHA-256 fingerprint in `rrt_whisper_hashes()` before it is saved. When a version constant in `whisper.php` changes, its fingerprints must be updated with it.

Fonts and the encoder are downloaded by the `rrt_local_fetch` action in steps, one request each: `encoder`, `fonts_plan` (reads Google's stylesheet and keeps the list in a transient for an hour), `font` (one file per request), then `fonts_finish` (writes `fonts.css` and records the link it was made from in the `rrt_local` option). The `encoder` step saves `mp3.wasm` after checking `RRT_MP3_SHA256`, and deletes a `lame.min.js` left from before 0.7.0; when `RRT_MP3_VERSION` changes, update the fingerprint and the version string `mp3.js` expects. The `model` step saves `rnnoise.wasm` after checking `RRT_RNNOISE_SHA256`. `denoise.js` calls the model by its minified export names, which belong to that exact file, so a new `RRT_RNNOISE_VERSION` means a new fingerprint and a check of those names. Fonts cannot have known fingerprints, since the link is the site's own choice, so each must come from fonts.gstatic.com, be woff2, and start with the woff2 signature.

## 8. The listening player

`rrt_player()` prints a `.rrt-player` element holding a normal `<audio controls>` (with a captions `<track>` when there is one) and the custom controls. Settings for the script travel in a `data-rrt` attribute, so there is no inline script for a caching plugin's optimiser to touch. `player.js` finds every `.rrt-player`, hides the native controls and wires up:

| Part | What it does |
|---|---|
| Controls | Play, drag or click the bar, slider keys (arrows 5 s, Page Up and Down 30 s, Home, End), skips, speed |
| Media Session | Lock screen title, artist, album and artwork; play, pause, skip and seek actions; position updates |
| Resume | `rrtResume_<postId>` in the listener's browser: last position (over 15 s) and when, kept 60 days |
| Start links | `?t=` or `#t=` in `1:45`, `105`, `1m45s` or `1h2m3s` form |
| Read along | Fetches the .vtt, wraps each word of the post text in a span the first time it is turned on, matches caption words to post words (looking up to 25 words ahead), times each word within its caption, and highlights the line and the word. Under 60% matched falls back to a transcript list |
| Events | `rrt:player` with `type` of view, play, pause, seek, rate, volume, progress (each 5 s bucket), hidden, visible, ended, leave, follow, start-link, follow-fallback |

The tokens printed for the player are scoped to `.rrt-player` and `.rrt-follow-root`, so the theme's own CSS variables are never changed.

**Placing it (1.28.0).** The top of a post or collection, the Reading player block and both shortcodes all go through `rrt_player_placed()`, which checks Show the player to, adds the preview note while it is for editors only, and draws each reading once per page: a reading drawn from the content, a widget area or the template is not drawn from another of them, while the same place may draw it again (content filtered twice). The top of the post gives way when `rrt_player_placed_by_hand()` finds the block or a shortcode for the post's own reading in its content or in the block template. Read along is offered only on the reading's own post; starting one player pauses the others (`pauseOthers`). `rrt_player()` itself stays a plain function for themes, with none of these rules.

## 9. Conventions

- ES5 style (`var`, function declarations) so the file runs without a build step in every browser in use.
- No em dashes in on-screen text.
- Every processing step is wrapped so a failure falls back and keeps the original recording available.
- New features add a comment heading so this map stays easy to update.
- Every visible word goes through the translation functions with the text domain `foxfire-studio`, whole sentences in one string (CONTRIBUTING.md, Translations).
